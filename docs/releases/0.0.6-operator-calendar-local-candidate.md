This local-only candidate adds:

- organization-scoped operator slot catalog reads and writes;
- reusable custom slot creation;
- date-specific custom slot instances;
- auditable `DRAFT → ACTIVE` and `DRAFT|ACTIVE → RETIRED` transitions;

## Internal Schedule API

All routes use `/api/internal/v1/schedule`. Reads require `operations.schedule.read` or `operations.schedule.write`; writes require `operations.schedule.write`.

- `GET /api/internal/v1/schedule/slot-offerings`
- `POST /api/internal/v1/schedule/slot-offerings`
- `POST /api/internal/v1/schedule/custom-slot-instances`
- `POST /api/internal/v1/schedule/compatibility-rules`
- `POST /api/internal/v1/schedule/slot-offerings/{id}:activate`
- `POST /api/internal/v1/schedule/slot-offerings/{id}:retire`
- `GET /api/internal/v1/schedule/calendar`

Cross-organization boat, slot, instance, template, transition, and pair IDs fail with stable `AUTHORIZATION_FAILED`. Creates, activation, retirement, and compatibility changes write audit rows. A canonical pair key and organization unique constraint preserve one rule per unordered pair.

No API mutates the clock time or identity of an existing definition. A changed used definition is represented by a new row. Retirement is terminal for future selection, while allocation/HOLD/booking snapshots remain unchanged.

## Calendar read model

The calendar accepts inclusive organization-local `from` / `to`, optional organization-scoped `boat_id`, and at most 31 local dates. Local midnight boundaries use the organization timezone, not the PHP/server timezone.

The response contains request and organization metadata, `as_of`, revision, boats, dates, applicable offering/instance identities, service and occupied intervals, and the status matrix:

| Projection status | Allocation authority / decision |
| --- | --- |
| `AVAILABLE` | no allocation, physical, compatibility, or definition-state conflict |
| `HELD` | ACTIVE HOLD allocation blocks the candidate |
| `CONFIRMED` | ACTIVE booking allocation blocks or directly owns the candidate |
| `BLOCKED` | ACTIVE operational block overlaps the candidate |
| `UNAVAILABLE` | inactive definition or compatibility-only conflict |

Physical occupied overlap uses `SLOT_UNAVAILABLE`. A denied same-day identified pair uses `SLOT_COMPATIBILITY_CONFLICT`. An explicit `ALLOW` cannot bypass physical occupied overlap. Candidate and allocation authority intervals are returned separately, including a `buffer_conflict` marker when service intervals do not overlap but occupied intervals do.

The projection returns no customer contact, lodging, room, price, payment, or seat fields. It does not write `stock_balances` or `cash_postings`.
