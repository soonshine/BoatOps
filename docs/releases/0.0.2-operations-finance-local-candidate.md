## 本地实现范围

### 主数据

- 付款来源账户：`CASH / BANK / COMPANY_CARD / EMPLOYEE_ADVANCE / OTHER`；
- 费用分类：`DIRECT / BOAT_DAILY / COMMON`；
- 饮料、食品、清洁、安全、维修及其他库存物品；
- 每个物品固定一个成本币种和计量单位。

### 燃油与费用

- 船只、可选出航、日期、加油站、升数、单价、总额；
- 加油前后油量、发动机小时、付款账户、经手人和凭证引用；
- `总额 = 升数 × 每升价格`，允许最多 1 个最小货币单位的舍入差；
- 一笔费用包含一个或多个分类明细，header 总额由明细原子求和；
- DIRECT/BOAT_DAILY 费用必须关联船只或可推导船只的出航；
- 付款账户与记录币种必须一致。

### 饮料与消耗品库存

支持：

```text
PURCHASE
→ LOAD（仓库到船）
→ CONSUME
→ RETURN（船到仓库）
→ WASTE
→ ADJUSTMENT_IN / ADJUSTMENT_OUT
```

- 以 `WAREHOUSE` 和 `BOAT:{id}` 保存独立余额；
- PURCHASE 必须记录与物品币种一致的付款账户和总成本；
- 同一物品写入时锁定 item 行并在事务内更新余额；
- 负库存被拒绝为 `INSUFFICIENT_STOCK`；
- 采购和正向调整重算移动平均成本；
- 装船/退回携带来源成本，消耗/损耗按来源移动平均成本确认；
- 库存写命令幂等，失败事务不得留下空余额或部分流水。

### 查询

- 每次出航按币种汇总燃油、费用和物资消耗/损耗成本；
- 每艘船按组织业务时区的本地日期汇总上述成本，并返回实际 UTC 区间；
- 查询仓库/船只库存数量、移动平均成本、库存价值和最低库存标记。

## API

写操作要求 `operations.finance.write` 和 `Idempotency-Key`：

- `POST /api/internal/v1/finance/accounts`
- `POST /api/internal/v1/finance/expense-categories`
- `POST /api/internal/v1/stock/items`
- `POST /api/internal/v1/fuel-logs`
- `POST /api/internal/v1/expenses`
- `POST /api/internal/v1/stock/movements`

查询要求 `operations.finance.read` 或 `operations.finance.write`：

- `GET /api/internal/v1/trips/{id}/cost-summary`
- `GET /api/internal/v1/boats/{id}/daily-cost-summary?date=YYYY-MM-DD`
- `GET /api/internal/v1/stock/balances`

Operations OpenAPI 已更新到 `1.0.0-alpha.2`。这些财务和成本接口是 BoatOps 私有接口，不进入 ChannelHub Inventory Provider API，也不发布包含成本的 Outbox 事件。
