## Deployment incident and recovery

The first atomic switch was rejected by live acceptance because a privileged preview had created file-cache entries that the production web user could not update. The automatic rollback restored the previous candidate immediately. No real data was involved.

The runtime cache and storage ownership was corrected, the candidate was re-tested under the same web user used in production, and the second atomic switch passed every live gate. A final external HTTP and real-browser run added no new application error.

## Explicit boundaries

- The public site contains only artificial demonstration data.
- The production-only one-time seed override was applied only to the dedicated seed command and remains false in the served environment.
- Browser pages receive no API token, bearer credential, database credential, or real customer information.
- Preset times are still `DEMO_DEFAULT_UNVERIFIED`; they are not the formal Plan A or Plan B operating schedule.
- GET simulation is not a HOLD or booking. Final HOLD and confirmation must be re-adjudicated by BoatOps transactional commands.
- ChannelHub, Google Sheet migration, OTA distribution, WordPress integration, payments, and real booking intake remain outside this release.
- `main` is unchanged. No Tag, GitHub Release, merge, or formal license grant was created.
