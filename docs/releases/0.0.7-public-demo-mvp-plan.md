# BoatOps 0.0.7 Public Demo MVP（Gate D0）

> **FROZEN PLAN / IMPLEMENTATION NOT YET ACCEPTED / NOT DEPLOYED / NOT RELEASED**

## 1. 目标

用最小改动把现有 BoatOps 能力整理成一个可安全公开访问、可在手机上演示的功能站，候选地址为：

- `https://boatops.ayany.com/demo`

第一版只证明一件事：BoatOps 能以“两艘整船 + 时间区间”为库存事实，正确展示预设档期、自定义档期以及选中一个档期后其他档期为何不可选。

本门禁基于提交 `be4e642f0db3460802d7bc6b6f3cc46c896fa6d8` 创建独立分支 `codex/boatops-v0.0.7-public-demo`。不得回写或扩大 `0.0.6 Gate B1` Draft PR 的冻结范围。

## 2. Demo MVP 页面

### 2.1 `/demo`：公开演示首页

- 明确显示“人工虚构数据 / 公开只读演示 / 不连接真实运营数据”；
- 显示 Plan A、Plan B 两艘虚构整船资源；
- 显示库存日历、档期规则两个主要入口；
- 保留现有燃油、费用、饮料/消耗品和现金活动的只读摘要，证明日常运营信息已有数据基础；
- 不显示新增、冲销、修改、删除等表单或按钮。

### 2.2 `/demo/calendar`：7 天库存日历与无写入预演

- 可按 Plan A / Plan B 筛选，并可前后翻 7 天；
- 展示五种虚构预设：全天 8 小时、全天 6 小时、上午 4 小时、下午 4 小时、下午 2.5 小时；
- 展示至少一个指定日期的虚构自定义档期；
- 访客可选择一个“模拟档期”，页面用既有服务端兼容/时间规则计算并标出：
  - 当前模拟选择；
  - 同船可继续选择的档期；
  - 同船不可选择的档期；
  - 不可选原因是时间重叠、缓冲重叠、明确兼容规则，还是既有 HOLD / CONFIRMED / BLOCK；
- 模拟选择只使用 GET 查询参数，不创建 HOLD、Booking、Allocation 或任何审计/财务记录；
- 页面明确注明“预演不是占位，最终 HOLD/确认仍由 BoatOps 事务重新裁决”。

### 2.3 `/demo/slots`：只读档期目录

- 显示五种预设、自定义模板、指定日期实例和适用船只；
- 显示档期状态、服务时间、占用时间/缓冲、运营时间状态和兼容规则；
- 隐藏创建、启用、停用、编辑兼容规则等全部写表单；
- 继续标注所有当前时间为 `DEMO_DEFAULT_UNVERIFIED` 或 `FICTIONAL_VALIDATION_SCENARIO`，不得暗示 Plan A / Plan B 真实时间已经冻结。

## 3. 公网安全模式

新增明确的 Demo 运行模式，禁止通过把生产环境伪装成 `local` 来开放页面：

- `disabled`：默认值，全部 `/demo` 返回 404；
- `local_write`：仅 `local/testing`，保留现有本地虚构写入测试能力；
- `public_read_only`：允许 `production`，但只开放公开 GET 页面。

`public_read_only` 必须同时满足：

1. `BOATOPS_DEMO_SITE_ENABLED=true`；
2. `BOATOPS_DEMO_SITE_MODE=public_read_only`；
3. 精确找到唯一的虚构组织、两艘虚构船和专用 Public Demo Reader；
4. Public Demo Reader 只有 `operations.finance.read` 与 `operations.schedule.read`，没有任何 write scope；
5. 所有 `/demo` POST 路由在公网模式返回 404 或 405，且数据库计数、revision 和流水不变化；
6. 页面响应带 `X-Robots-Tag: noindex, nofollow, noarchive`、`Cache-Control: no-store`，并启用合理的 GET 限流；
7. `APP_ENV=production`、`APP_DEBUG=false`，浏览器端不存在 Bearer Token、Demo Token 或其他凭据。

Public Demo 必须使用独立的纯虚构数据库或独立虚构实例，不得和未来真实客户、真实财务或 Google Sheet 导入库混用。

## 4. 必须可见的演示场景

Seeder 使用相对当前曼谷日期生成稳定的虚构场景，重复执行不得复制数据：

1. Plan A 某日有全天档期占用，其他同船档期显示不可售；
2. Plan A 某日有上午档期或规则冲突，页面能说明下午档期是否可组合及原因；
3. Plan B 同日保持独立，Plan A 的选择不能误锁 Plan B；
4. 某日出现指定日期自定义档期，并按 fail-closed 兼容规则展示；
5. 至少展示一个 HOLD、一个 CONFIRMED 和一个 BLOCK 对日历投影的影响；
6. 首页展示虚构燃油、费用、饮料/消耗品和现金活动摘要，但不能执行写入。

## 5. 本门禁明确排除

- 真实客户、手机号、邮箱、酒店、价格、合同、确认单或财务数据；
- 公开创建 HOLD、确认、改期、取消、封船或订单后台；
- 登录、角色后台、支付、退款、凭证上传、审批与完整利润；
- Google Sheet 导入、迁移或双向同步；
- ChannelHub、OTA、WordPress 或 ayany.com 主站对接；
- 冻结 Plan A / Plan B 真实档期起止时间和周转缓冲；
- Tag、GitHub Release、正式许可证声明或“生产可用”宣传。

## 7. 验收标准

只有以下项目全部有证据，Gate D0 才能判定 PASS：

- `/demo`、`/demo/calendar`、`/demo/slots` 未登录访问均为 200；
- 页面只出现人工虚构内容，且没有写按钮、真实资料或浏览器凭据；
- 选择模拟档期后，页面能正确解释同船冲突，另一艘船不受影响；
- 自定义档期可见，且未把虚构时间写成真实运营时间；
- 对既有 Demo POST 地址逐一请求均不能写入，前后数据库摘要完全一致；
- 全部自动化测试、格式、契约、构建、依赖、secret 和 PII 检查通过；
- `APP_ENV=production`、`APP_DEBUG=false`，响应头和限流生效；
- 公网桌面与手机视觉 QA 通过；
- 能回滚到部署前候选版本，并保留命令结果、时间、commit 与 SHA-256 证据；
- 未修改 `main`，未合并 Draft PR，未创建 Tag 或 Release。
