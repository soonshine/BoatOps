## 更正语义

更正 = 冲销原记录 + 使用现有正常创建端点重录。系统没有、也不提供 update/delete 金额接口。原记录保留并改为 `REVERSED`，重录产生新的 `POSTED` 记录和独立外部引用。

## 三个冲销资源端点

全部要求 `operations.finance.write`、UUID `Idempotency-Key`、组织上下文、`external_reference` 和必填 `reason`：

- `POST /api/internal/v1/fuel-logs/{id}:reverse`
- `POST /api/internal/v1/expenses/{id}:reverse`
- `POST /api/internal/v1/stock/movements/{id}:reverse`

燃油与费用冲销将原状态改为 `REVERSED`。库存冲销在同一事务中生成一条精确反向的 `REVERSAL` 补偿流水并更新余额；补偿流水可识别、关联 `reversal_of_movement_id`，且不能再次冲销。成本汇总只统计适用的 `POSTED` 正常流水，不把补偿重复计入成本。

每次成功冲销在 `finance_reversals` 保存原资源类型/ID、原因、服务端冲销时间、actor 和可选库存补偿 movement ID。原状态、冲销事实、库存补偿/余额、`audit_logs` 与 `idempotency_keys` 原子提交；稳定业务失败回滚，不留部分写入。同一组织内外部引用及原记录冲销关系唯一；所有资源查找按组织隔离，跨组织 ID 返回授权失败。

## 本地 demo 操作台

`/demo` 继续采用默认关闭、仅 `local/testing`、精确虚构组织及最小权限 actor 的 404 fail-closed 门禁。页面分区展示最近燃油、费用和库存流水，包括 `POSTED`、`REVERSED` 与不可再次冲销的库存 `REVERSAL` 补偿；使用组织时区显示发生时间、冲销原因、服务端冲销时间和补偿 movement ID。

只有可冲销的 `POSTED` 原记录渲染行内 CSRF 表单。每行在服务端生成独立 UUID `command_id`；浏览器不填写 API token、Bearer secret 或 client secret。demo controller 只按固定类型分派给三个正式 controller/service 冲销入口，传入正式 API 的 payload 仅含 `external_reference` 与 `reason`，不复制事务、库存或冲销规则。controller、demo view 与 seeder 均不直接写 `stock_balances`。
